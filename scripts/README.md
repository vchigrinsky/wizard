# Автоматизация двухузловой схемы

Три скрипта, закрывающие путь от «есть IP и пароль» до «маршрут проверен и
размечен». Всё, что в `docs/01-setup-vpn.md` делается руками через веб-панель,
здесь делается через API 3x-ui.

Зависимостей нет — только стандартная библиотека Python 3.10+, `ssh` и `curl`.
Для шага 2 дополнительно нужен `xray` (`brew install xray`).

Общий модуль — `vpnkit.py`; напрямую он не запускается.

## Соглашения

Алиас узла — это `<хостинг>_<страна>`: `timeweb_ru`, `selectel_kz`,
`bigvds_nl`. Из него выводится всё остальное, руками ничего вводить не нужно:

| что | как называется | пример |
| --- | --- | --- |
| SSH-ключ | `~/.ssh/id_ed25519_vps_<алиас>_<IP>` | `id_ed25519_vps_selectel_kz_153.80.200.9` |
| хост в `~/.ssh/config` | `<алиас>_<IP>` | `selectel_kz_153.80.200.9` |
| inbound на обоих узлах | `main` | `main` |
| клиент на зарубежном узле | `main-from-<хостинг>-<страна>` | `main-from-vpsville-ru` |
| клиент на российском узле | `vvchigrinskii-to-<хостинг>-<страна>` | `vvchigrinskii-to-selectel-kz` |
| outbound на российском узле | `<хостинг>-<страна>-main` | `selectel-kz-main` |
| метка маршрута | `<флаг> <хостинг> ← <флаг> <хостинг>` | `🇰🇿 selectel ← 🇷🇺 vpsville` |

## Шаг 0 — SSH-ключ под новый сервер

```bash
python scripts/vpn_ssh_key.py ALIAS IP PASSWORD [USER]
```

```bash
python scripts/vpn_ssh_key.py selectel_kz 153.80.200.9 'пароль_рута'
python scripts/vpn_ssh_key.py bigvds_nl 109.104.153.242 'пароль' ubuntu
```

Создаёт ключ, кладёт публичную половину на сервер (пароль спрашивается ровно
один раз и только здесь), дописывает блок в `~/.ssh/config` и проверяет вход.
Если хостинг сразу выдал готовый ключ — шаг не нужен, достаточно самому
прописать `Host` в том же формате.

Пароль передаётся серверу через псевдотерминал, `sshpass` и `paramiko` не
нужны. Существующий ключ не перезаписывается.

## Шаг 1 — собрать связку

```bash
python scripts/vpn_build_route.py ALIAS_RU ALIAS_FOREIGN
```

```bash
python scripts/vpn_build_route.py vpsville_ru selectel_kz
```

Полностью воспроизводит инструкцию:

1. если на узле пусто — `apt update && upgrade`, перезагрузка при
   необходимости, подбор свободного порта (443 → 8443 → 2053), неинтерактивная
   установка 3x-ui `v3.5.0` и откат ядра Xray на `v26.6.27`;
2. на зарубежном узле — inbound `main` (Reality под `www.google.com`) и клиент
   `main-from-…`;
3. на российском — inbound `main` (Reality под `www.yandex.ru`), клиент
   `vvchigrinskii-to-…`, outbound на зарубежный узел и routing rule;
4. проверяет хоп «российский узел → зарубежный» силами самой панели и печатает
   страну выхода с задержкой;
5. забирает vless-ссылку, подменяет метку и дописывает в `vless.md`.

Каждый шаг идемпотентен: что уже настроено — переиспользуется. Повторный
запуск на собранной связке ничего не меняет и не трогает `vless.md`. Если
зарубежный узел пересоздали и ключи Reality сменились, устаревший outbound
переписывается автоматически.

Ссылка в `vless.md` не перезаписывается из-за косметики: панель выдаёт `sid`
случайным из пула, поэтому сравниваются только значимые поля — UUID, адрес,
порт, публичный ключ, SNI.

Путь к файлу меняется флагом `--vless-file`.

## Шаг 2 — проверить маршруты

```bash
python scripts/vpn_check_routes.py vless.md
```

Берёт каждый неразмеченный маршрут, поднимает под него локальный `xray` с
SOCKS-прокси, смотрит страну выхода и дописывает к заголовку ✅ или ❌.
Результат пишется после каждого маршрута, так что прерванный прогон не теряет
уже сделанное.

Флаги: `--recheck` — перепроверить в том числе размеченные; `--skip-baseline` —
не проверять исходное состояние; `--to-clipboard` — положить все ссылки в
буфер обмена, чтобы импортировать их в v2RayTun одной пачкой.

### Почему не v2RayTun

У v2RayTun на macOS нет ни CLI, ни AppleScript-словаря — только URL-схема
`v2raytun://` на импорт. Включать и выключать туннель программно нечем,
пришлось бы кликать по интерфейсу. Вдобавок системный VPN уводит в туннель
весь трафик машины, включая саму проверку. Локальный `xray` с SOCKS-прокси
проверяет тот же маршрут теми же протоколами, но трогает только те запросы,
которые через него пустили. Для самого v2RayTun есть `--to-clipboard`.

### Критерии

Один раз на старте, напрямую мимо туннеля: 2ip.ru должен показывать Россию —
это то же самое, что в v2RayTun обеспечивает раздельное туннелирование.
Проверяется однократно, потому что прямой трафик машины от маршрута к маршруту
не меняется.

По каждому маршруту, через туннель: страна выхода должна совпасть со страной
зарубежного узла из названия. Опрашивается несколько гео-сервисов, и маршрут
засчитывается, если ожидаемую страну подтвердил хотя бы один — базы у них
расходятся, и по одному источнику легко получить ложный ❌.

## Массовый прогон

```bash
for ru in timeweb_ru selectel_ru vpsville_ru; do
  for foreign in timeweb_nl selectel_kz selectel_uz bigvds_nl; do
    python scripts/vpn_build_route.py "$ru" "$foreign" || echo "СБОЙ: $ru → $foreign"
  done
done
python scripts/vpn_check_routes.py vless.md
```

## Осторожно

`vless.md` — это живые ключи доступа к вашему ВПН. Файл добавлен в
`.gitignore` и в `exclude` Jekyll: в публичный репозиторий и на сайт он
попасть не должен.
