# Автоматизация двухузловой схемы

Три скрипта, закрывающие путь от «есть IP и пароль» до «маршрут проверен и
размечен». Всё, что в `docs/01-setup-vpn.md` делается руками через веб-панель,
здесь делается через API 3x-ui.

Зависимостей нет — только стандартная библиотека Python 3.10+, `ssh` и `curl`.
Для шага 2 дополнительно нужен `xray` (`brew install xray`).

Общий модуль — `vpnkit.py`; напрямую он не запускается.

## Соглашения

Алиас узла — это `<хостинг>_<страна>`: `timeweb_ru`, `selectel_kz`,
`bigvds_nl`. Из него выводится всё остальное, руками ничего вводить не нужно:

| что | как называется | пример |
| --- | --- | --- |
| SSH-ключ | `~/.ssh/id_ed25519_vps_<алиас>_<IP>` | `id_ed25519_vps_selectel_kz_153.80.200.9` |
| хост в `~/.ssh/config` | `<алиас>_<IP>` | `selectel_kz_153.80.200.9` |
| inbound на обоих узлах | `main` | `main` |
| клиент на зарубежном узле | `main-from-<хостинг>-<страна>` | `main-from-vpsville-ru` |
| клиент на российском узле | `vvchigrinskii-to-<хостинг>-<страна>` | `vvchigrinskii-to-selectel-kz` |
| outbound на российском узле | `<хостинг>-<страна>-main` | `selectel-kz-main` |
| метка маршрута | `<флаг> <хостинг> ← <флаг> <хостинг>` | `🇰🇿 selectel ← 🇷🇺 vpsville` |
| метка узла в `panels.md` | `<флаг> <хостинг>` | `🇰🇿 selectel` |

Рабочих файла два, оба лежат в корне репозитория и оба в `.gitignore`:
`vless.md` — ключи маршрутов, `panels.md` — доступы к панелям 3x-ui.

## Сортировка

Любой прогон, который трогает `vless.md` или `panels.md`, оставляет файл
отсортированным — в том числе когда сама запись не менялась, а порядок
остался кривым с прошлых раз. Порядок задан по зарубежному узлу: сначала его
хостинг, потом страна, а внутри — российский узел.

```text
🇳🇱 bigvds   ← 🇷🇺 selectel      🇳🇱 bigvds
🇳🇱 bigvds   ← 🇷🇺 timeweb       🇰🇿 selectel
🇰🇿 selectel ← 🇷🇺 selectel      🇷🇺 selectel
🇰🇿 selectel ← 🇷🇺 timeweb       🇺🇿 selectel
🇺🇿 selectel ← 🇷🇺 selectel      🇳🇱 timeweb
🇳🇱 timeweb  ← 🇷🇺 timeweb       🇷🇺 timeweb
```

Переставляются только секции целиком, вместе с заголовком, содержимым и
отметками ✅/❌ — тексты не трогаются. Заголовки, которые не удалось разобрать,
уезжают в конец, сохраняя исходный порядок между собой.

## Шаг 0 — SSH-ключ под новый сервер

```bash
python scripts/vpn_ssh_key.py ALIAS IP PASSWORD [USER]
```

```bash
python scripts/vpn_ssh_key.py selectel_kz 153.80.200.9 'пароль_рута'
python scripts/vpn_ssh_key.py bigvds_nl 109.104.153.242 'пароль' ubuntu
```

Создаёт ключ, кладёт публичную половину на сервер (пароль спрашивается ровно
один раз и только здесь), дописывает блок в `~/.ssh/config` и проверяет вход.
Если хостинг сразу выдал готовый ключ — шаг не нужен, достаточно самому
прописать `Host` в том же формате.

Пароль передаётся серверу через псевдотерминал, `sshpass` и `paramiko` не
нужны. Существующий ключ не перезаписывается.

## Шаг 1 — собрать связку

```bash
python scripts/vpn_build_route.py ALIAS_RU ALIAS_FOREIGN
```

```bash
python scripts/vpn_build_route.py vpsville_ru selectel_kz
```

Полностью воспроизводит инструкцию:

1. если на узле пусто — `apt update && upgrade`, перезагрузка при
   необходимости, подбор свободного порта (443 → 8443 → 2053), неинтерактивная
   установка 3x-ui `v3.5.0` и откат ядра Xray на `v26.6.27`;
2. на зарубежном узле — inbound `main` (Reality под `www.google.com`) и клиент
   `main-from-…`;
3. на российском — inbound `main` (Reality под `www.yandex.ru`), клиент
   `vvchigrinskii-to-…`, outbound на зарубежный узел и routing rule;
4. записывает доступы к панелям обоих узлов в `panels.md`;
5. проверяет хоп «российский узел → зарубежный» силами самой панели и печатает
   страну выхода с задержкой;
6. забирает vless-ссылку, подменяет метку и дописывает в `vless.md`.

Каждый шаг идемпотентен: что уже настроено — переиспользуется. Повторный
запуск на собранной связке ничего не меняет и не трогает `vless.md`. Если
зарубежный узел пересоздали и ключи Reality сменились, устаревший outbound
переписывается автоматически.

Ссылка в `vless.md` не перезаписывается из-за косметики: панель выдаёт `sid`
случайным из пула, поэтому сравниваются только значимые поля — UUID, адрес,
порт, публичный ключ, SNI.

Пути к файлам меняются флагами `--vless-file` и `--panels-file`.

## Доступы к панелям

```bash
python scripts/vpn_panel_creds.py ALIAS
```

```bash
python scripts/vpn_panel_creds.py timeweb_ru
```

Забирает с узла адрес панели, логин и пароль и дописывает их в `panels.md`.
Если запись про этот узел уже есть — ничего не делает.

Инструмент атомарный: только читает и записывает, панель не ставит и не
настраивает. Отдельно он нужен для узлов, которые настраивались раньше или
руками; в рамках сборки связки то же самое делается автоматически для обоих
узлов, ставилась там панель только что или стояла давно.

Источник данных — `/etc/x-ui/install-result.env`, файл, который установщик
3x-ui оставляет на сервере. Значения там записаны через `printf %q`, поэтому
файл не парсится вручную: его читает шелл на самой машине и отдаёт уже
развёрнутые значения.

Формат записи:

```markdown
## 🇷🇺 timeweb
- URL: http://72.56.236.30:34748/ZiJV9haUkIdqP4PLeq
- Логин: ZG4QGzrwX2
- Пароль: fHDQxmqoN6
```

## Шаг 2 — проверить маршруты

```bash
python scripts/vpn_check_routes.py vless.md
```

Берёт каждый неразмеченный маршрут, поднимает под него локальный `xray` с
SOCKS-прокси, смотрит страну выхода и дописывает к заголовку ✅ или ❌.
Результат пишется после каждого маршрута, так что прерванный прогон не теряет
уже сделанное.

Флаги: `--recheck` — перепроверить в том числе размеченные; `--only ПОДСТРОКА` —
взять только маршруты с этой подстрокой в названии; `--to-clipboard` — положить
все ссылки в буфер обмена, чтобы импортировать их в v2RayTun одной пачкой.
Параметры нагрузки: `--traffic-mb`, `--streams`, `--traffic-timeout`,
`--min-speed`.

### Системный VPN нужно выключить

Перед работой скрипт смотрит, куда уходит маршрут по умолчанию. Если поднят
v2RayTun или другой клиент в режиме TUN, весь трафик машины идёт через него —
включая исходящие соединения нашего локального `xray` к российским узлам.
Локальный туннель оказывается вложенным в чужой, REALITY-хендшейк внутри него
разваливается, и проверка забракует все маршруты подряд, включая исправные.

В таком случае скрипт останавливается и просит выключить системный VPN.
Продавить можно флагом `--allow-system-vpn`, но результатам верить будет
нельзя.

### Почему не v2RayTun

У v2RayTun на macOS нет ни CLI, ни AppleScript-словаря — только URL-схема
`v2raytun://` на импорт. Включать и выключать туннель программно нечем,
пришлось бы кликать по интерфейсу. Вдобавок системный VPN уводит в туннель
весь трафик машины, включая саму проверку. Локальный `xray` с SOCKS-прокси
проверяет тот же маршрут теми же протоколами, но трогает только те запросы,
которые через него пустили. Для самого v2RayTun есть `--to-clipboard`.

### Критерии

Галочка ставится, только если прошли обе проверки.

**Страна.** Выход через туннель должен оказаться в стране зарубежного узла из
названия маршрута. Опрашивается несколько гео-сервисов, и засчитывается
совпадение хотя бы по одному — базы у них расходятся, и по одному источнику
легко получить ложный ❌.

**Нагрузка.** По маршруту прогоняется заметный объём в несколько параллельных
соединений: по умолчанию 32 МБ в 4 потока с порогом 2 Мбит/с. Маршрут валится,
если соединение оборвалось, докачалось не всё или средняя скорость ушла ниже
порога.

Одной проверки страны недостаточно, и это выяснилось на практике: ТСПУ
спокойно пропускают короткий запрос на пару килобайт, поэтому маршрут
отвечает на гео-запрос, показывает правильную страну — и при этом непригоден
для реального пользования, потому что поток душится. Нагрузочная проба
имитирует то, как маршрут нагружает обычный браузер, и такие случаи ловит.

Проверки «2ip.ru показывает Россию» здесь намеренно нет. Она имела бы смысл
только как контроль раздельного туннелирования в v2RayTun; через SOCKS-прокси
прямой трафик машины вообще не меняется, так что она измеряла бы ваше
собственное подключение, а не маршрут.

## Использовать узлы как обычный прокси

```bash
python scripts/vpn_proxy.py --list
python scripts/vpn_proxy.py 'timeweb ← 🇷🇺 timeweb'
```

Поднимает локальный `xray`, который принимает SOCKS5 (порт 1080) и HTTP
(порт 1081) и заворачивает их в выбранный VLESS/REALITY-маршрут. Порты
меняются флагами `--socks-port` и `--http-port`. Процесс держится, пока
пользуетесь; остановка — Ctrl+C.

На серверах ничего поднимать и менять не нужно: маршрут уже есть, не хватало
только локальной головы, которая переведёт привычный прокси-протокол в этот
транспорт.

Куда подставлять:

```bash
export HTTP_PROXY=http://127.0.0.1:1081
export HTTPS_PROXY=http://127.0.0.1:1081
export NO_PROXY=localhost,127.0.0.1,::1
```

ZeroOmega — профиль типа Proxy, протокол SOCKS5, сервер `127.0.0.1`, порт
`1080`. Системный прокси macOS — `networksetup -setsecurewebproxy "Wi-Fi"
127.0.0.1 1081`.

Инбаунда два не для красоты: `HTTP_PROXY` с SOCKS понимают не все клиенты
(curl и git — да, requests без отдельной зависимости — нет), а HTTP-инбаунд
принимает и обычные запросы, и CONNECT для HTTPS, поэтому годится всем.

### Фоновый режим

```bash
python scripts/vpn_proxy.py 'ishosting ← 🇷🇺 beget' --install-agent
python scripts/vpn_proxy.py --status
python scripts/vpn_proxy.py --uninstall-agent
```

Ставит прокси агентом launchd: поднимается сам, переживает перезагрузку,
терминал держать не нужно. Конфиг с ключом кладётся в
`~/Library/Application Support/vpnkit/proxy.json` с правами `600`, лог —
в `~/Library/Logs/vpnkit-proxy.log`.

Так удобно снимать системный TUN: ВПН выключен, сеть родная, а отдельное
приложение (например, Claude) ходит через прокси по своей переменной
окружения. Для Claude это `env` в `~/.claude/settings.json`.

### Почему не демон на сервере

Соблазнительно поставить на узел dante, 3proxy или squid и ходить прямо на
него. Так делать не стоит: трафик от вас до сервера пойдёт открытым
прокси-протоколом, без маскировки под TLS, и ТСПУ опознает его сразу — то есть
потеряется ровно то, ради чего в схеме используется REALITY. Вдобавок появится
открытый порт с паролем, который начнут перебирать. Локальная голова оставляет
канал до узла неотличимым от обычного TLS.

## Прямые клиенты — подключение без российского узла

```bash
python scripts/vpn_direct.py --all              # все зарубежные узлы
python scripts/vpn_direct.py bigvds_nl          # выбранный
python scripts/vpn_direct.py --all --drop       # снять
python scripts/vpn_check_routes.py direct.md    # проверить
```

Заводит в том же inbound'е `main` отдельного клиента `vvchigrinskii-direct` и
складывает ссылки в `direct.md` (тоже живые ключи, тоже в `.gitignore`).

Основная схема двухузловая, и это правильно для повседневного пользования. Но
для изучения фильтрации она неудобна: между нами и заграницей стоит наш же
российский узел, и по одному лишь факту «не работает» непонятно, на каком из
двух участков рвётся. Прямой клиент убирает посредника и даёт чистый
подопытный участок «российская сеть → зарубежный адрес».

Узлы `beget_ru` и все `ishosting` в `--all` не попадают: на них живая
инфраструктура, экспериментировать там нельзя. Список зашит в `FORBIDDEN`.

## Диагностика фильтрации

Три самостоятельных инструмента без внешних зависимостей — копируются на любой
узел и запускаются прямо там, потому что интересна не наша машина, а участок
пути.

```bash
scp scripts/netprobe.py УЗЕЛ:/tmp/
ssh УЗЕЛ 'python3 /tmp/netprobe.py цель=1.2.3.4 контроль=5.6.7.8 \
    --cases tcp,tls12:www.google.com,tls12:example.com,tls-slice:www.google.com:40'
```

`netprobe.py` — матрица проб. Меняет по одному признаку (адрес, порт, наличие
и значение SNI, размер первого пакета, разрезан ли он на сегменты) и
различает способы смерти соединения: молчаливый `timeout` (пакет съели),
`rst` (убили инъекцией), `eof`, `ok`. Это различие важнее самого факта
неработоспособности: за ними стоят разные механизмы.

```bash
ssh УЗЕЛ 'python3 /tmp/filter_census.py цель=1.2.3.4 --snis a.com,b.com \
    --cycles 3 --delay 4 --shuffle'
ssh УЗЕЛ 'python3 /tmp/filter_census.py цель=1.2.3.4 --freeze --burst 8'
ssh УЗЕЛ 'python3 /tmp/filter_census.py цель=1.2.3.4 --ramp 2,3,4,6,8'
```

`filter_census.py` отделяет три причины одного и того же наблюдения: список
имён, ограничение по частоте и просто потери. Гоняет имена вперемешку по
нескольким циклам с паузами; если результат по имени повторяется независимо
от места в очереди — это список, если «плохими» оказываются каждый раз разные
имена — это частота. Режимы `--freeze` и `--ramp` бьют по частоте прицельно:
свежим, ни разу не использованным именем, чтобы прошлая заморозка не утекала
в новый замер.

```bash
ssh УЗЕЛ 'sudo python3 /tmp/ttl_trace.py 1.2.3.4 \
    --blocked www.google.com --allowed example.com'
```

`ttl_trace.py` ищет хоп, на котором пакет съедают. Фильтр не отвечает и в
обычной трассировке не виден, поэтому используется косвенный признак:
приветствие TLS отправляется с заниженным TTL. Пока TTL меньше расстояния до
фильтра, пакет умирает раньше и маршрутизатор честно присылает ICMP; как
только фильтр дотягивается — ICMP пропадает. Первый «пропавший» хоп и есть
искомый. Второе, безобидное имя проходит насквозь и даёт полную карту пути
для сравнения. Нужен root: ICMP принимается сырым сокетом.

Метод упирается в потолок там, где маршрутизаторы не отвечают на истёкший TTL
вовсе — тогда он даёт не точку, а промежуток.

## Зона белых списков — полевой зонд

Главный инструмент для поездки. Отвечает не на вопрос «что работает» (в этом
режиме почти ничего), а на вопрос **по какому признаку пускают** — потому что
от этого и только от этого зависит, какую схему обхода вообще имеет смысл
строить.

### Перед выездом, дома

```bash
# маяки на узлы (один раз, дальше живут сами)
scp scripts/blackout_beacon.py УЗЕЛ:/opt/
ssh УЗЕЛ 'sudo python3 /opt/blackout_beacon.py --install'

# репетиция: убедиться, что всё отвечает
python3 scripts/whitelist_probe.py
```

Дома вывод должен быть «белые списки НЕ включены». Если так — инструмент
исправен и эталон снят, будет с чем сравнивать.

### На месте, когда ограничения включены

```bash
python3 scripts/whitelist_probe.py            # полный прогон, минуты две
python3 scripts/whitelist_probe.py --quick    # только главная матрица, секунды
python3 scripts/whitelist_probe.py --watch    # по кругу, ловить включение режима
```

Аргументы не нужны: адреса узлов берутся из `~/.ssh/config`. Журнал в JSONL
кладётся рядом со скриптом, забирать можно в любой момент, не останавливая.

`--watch` полезен, если режим то включают, то выключают: скрипт будет писать
круг за кругом, и по журналу потом видно точное время переключения.

### Как читать вывод

Всё держится на перекрёстной матрице «имя против адреса»:

|                     | адрес разрешённый | адрес наш (не в списке) |
| ------------------- | ----------------- | ----------------------- |
| **имя разрешённое** | контроль          | **главный вопрос**      |
| **имя чужое**       | второй вопрос     | контроль                |

Скрипт сам печатает вердикт, но логика такая:

* **разрешённое имя проходит на наш адрес** — смотрят только имя. Лучший
  исход: спасает подстановка SNI, покупать ничего не нужно;
* **чужое имя проходит на разрешённый адрес** — смотрят только адрес. Нужен
  вход внутри разрешённого адресного пространства, имена бесполезны;
* **не проходит ни то, ни другое** — проверяют оба признака. Самый тяжёлый
  случай;
* **проходит всё** — режим не включён, замер надо переснять позже.

Дальше идут: большой перебор имён по группам (93 имени — разрешённые,
заблокированные, зарубежные, в разном регистре, с суффиксными трюками),
карта уцелевших портов и протоколов, проба на отсечку по объёму, HTTP с
подменой заголовка `Host` и трассировка.

### Почему адреса берутся не у оператора

Скрипт добывает адреса целей через публичные резолверы, а не через системный.
В зоне ограничений резолвер оператора первым начинает врать или молчать — и,
поверив ему, мы стучались бы в пустоту, приняв это за блокировку. Расхождение
ответов между резолверами скрипт отмечает отдельно: это признак подмены.

### Когда вернётесь

Забрать журнал зонда и журналы маяков:

```bash
ssh УЗЕЛ 'sudo python3 /opt/blackout_beacon.py --report'
```

Сопоставление двух сторон отвечает на вопрос, который с одной стороны
неразрешим: пакет не ушёл или ушёл, дошёл, но обратно не пустили.

## Замеры в отрезанной сети

Комплект из двух частей для случая, когда включён режим белых списков:
связи нет, спросить совета не у кого, а данные собрать надо.

### Маяк — на серверы, заранее

```bash
scp scripts/blackout_beacon.py УЗЕЛ:/opt/
ssh УЗЕЛ 'sudo python3 /opt/blackout_beacon.py --install'
ssh УЗЕЛ 'sudo python3 /opt/blackout_beacon.py --report'   # что долетало
```

Слушает сразу несколько портов, и TCP, и UDP, отвечает опознавательным
маркером и по запросу отдаёт поток заданного объёма. Ставится службой
systemd, переживает перезагрузку. Журнал — `/opt/beacon-log.jsonl`.

Половина ценности маяка — именно журнал. Зонд на ноутбуке видит только «ответ
пришёл» или «не пришёл», а это два разных диагноза: пакет не вышел или вышел,
дошёл, но обратно не пустили. С одной стороны их не различить. Запись в
журнале маяка доказывает, что пакет дошёл.

Из приветствия TLS маяк вытаскивает имя — видно, с каким SNI до него реально
добрались.

### Зонд — на ноутбук, в поле

```bash
python3 scripts/blackout_probe.py              # круг за кругом
python3 scripts/blackout_probe.py --once       # один проход
python3 scripts/blackout_probe.py --no-deep    # без пробы объёма, быстрее
```

Аргументы не обязательны: адреса маяков берутся из `~/.ssh/config`, свои
маршруты — из `vless.md` и `direct.md`. Журнал в JSONL кладётся рядом со
скриптом, забирать его можно в любой момент, не останавливая прогон.

Что выясняет:

* **на каком уровне закрыто** — имя не разрешается (DNS), адрес не отвечает
  (маршрутизация) или TCP есть, а рукопожатие пропадает (SNI);
* **главный вопрос: разрешённое имя на неразрешённом адресе.** Живёт — фильтр
  смотрит только на имя, спасает подстановка SNI. Умирает — нужен вход внутри
  разрешённого адресного пространства, и ухищрения с именами бесполезны;
* **есть ли отсечка по объёму** — маяк отдаёт мегабайт, зонд считает, сколько
  дошло до затыка. Обрыв на 16–20 КБ и есть известная механика белых списков;
* что живо из другой физики — UDP, ICMP, трассировка;
* подают ли признаки жизни уже настроенные маршруты.

### Порядок в поле

1. Заранее, дома: поставить маяки, прогнать `blackout_probe.py --once` и
   убедиться, что всё отвечает.
2. На месте, когда ограничения включены: запустить без аргументов и оставить.
3. Вернувшись: забрать журнал зонда и журналы маяков (`--report`) и свести.

## Массовый прогон

```bash
for ru in timeweb_ru selectel_ru vpsville_ru; do
  for foreign in timeweb_nl selectel_kz selectel_uz bigvds_nl; do
    python scripts/vpn_build_route.py "$ru" "$foreign" || echo "СБОЙ: $ru → $foreign"
  done
done
python scripts/vpn_check_routes.py vless.md
```

## Осторожно

`vless.md` — это живые ключи доступа к вашему ВПН, `direct.md` — то же самое
для прямых подключений, а `panels.md` — логины и пароли от админок узлов. Все
три добавлены в `.gitignore` и в `exclude` Jekyll: в публичный репозиторий и
на сайт они попасть не должны.
