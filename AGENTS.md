## Приоритет инструкций

Этот файл — handoff для агента, который открывает проект в чистой сессии. Он действует для всей директории. Прямые указания пользователя всегда важнее написанного ниже.

Перед любыми изменениями сначала прочитайте этот файл целиком, затем целиком прочитайте файл, которого касается задача. Не восстанавливайте контекст по одному абзацу или заголовку.

## Что это за проект

Проект посвящён Telegram-каналу [@vuutya](https://t.me/vuutya) про интересные прикладные ИТ-штуки: VPN, сетевые конфигурации, саморазвёрнутые сервисы и похожие эксперименты.

Основной формат материалов — самостоятельные лонгриды. План публикации:

- веб-страница для чтения по ссылке из Telegram;
- исходный Markdown для офлайн-распространения и передачи ИИ-агентам;
- PDF-копия для офлайн-чтения.

Первые два материала посвящены личному VPN «ВПН ВИКТОР» и самостоятельной сборке аналогичной двухузловой схемы.

### Потенциально подозрительное место во второй статье

В разделе «Создайте outbound на российском сервере» сейчас есть пункт:

```markdown
- **Security:** значение `REALITY_PORT` из ссылки...
```

По смыслу здесь может подразумеваться поле **Port**, тогда как **Security** должно иметь значение `Reality`. Кроме того, выше `UUID` объявлен необходимым значением, но далее явно не вводится ни в одно поле. Пользователь объявил инструкцию готовой, поэтому **не исправляйте это молча**. Если возобновится пошаговая техническая проверка, сначала сверяйтесь с интерфейсом именно 3x-ui `v3.5.0` и уточните изменение у пользователя.

### `xui-bandwidth-app.py`

Самостоятельный Python-сервис мониторинга трафика 3x-ui без сторонних библиотек. Он:

- читает `/etc/x-ui/x-ui.db`;
- сопоставляет пользователей маршрутам NL/KZ по outbound-тегам;
- считает скорость за окна 1, 10, 60 и 300 секунд;
- поднимает веб-интерфейс и endpoint `/api`;
- поддерживает токен через `BWMON_TOKEN`;
- использует переменные `XUI_DB`, `BWMON_STATE_DB`, `BWMON_HOST` и `BWMON_PORT`.

Сервис пока не описан ни в одной статье, для него нет инструкции установки и тестового набора. Возможно, он станет основой одного из следующих постов, но это ещё не решено.

Backup не редактировать и не удалять без прямой просьбы. В `_config.yml` оба Python-файла и `AGENTS.md` исключены из сборки сайта (`exclude`), но остаются в git.

## Редакционный стиль

### Голос и тон

- Язык — русский.
- Базовый тон сухой, спокойный и практический: коротко, ёмко, без официоза, рекламной подачи и «нейрослопа», но не телеграфными обрубками.
- Каждый абзац раскрывает одну законченную мысль. Смысловую нагрузку распределяйте равномерно; не перегружайте один участок и не повторяйте уже сказанное.
- Обращение к читателю — на «вы» со строчной буквы и во множественном числе: «откройте», «выберите», «у вас».
- Автор говорит о себе в первом лице единственного числа только там, где важен личный опыт: «я проверил», «я использую», «по моему опыту».
- Не переходите на «мы настроим», «теперь сделаем» и не пишите «Вы», «Вам», «Вас» с прописной буквы.

Интонация преимущественно серьёзная, но в тексте намеренно оставлены редкие разговорные вкрапления и сухой юмор: «соболезную», «светлая демократия», «буквами Ы», «туземский», «приколдесы», «проблема курицы и яйца», «танец с бубном», «путь вайбкодера», «путь истинного самурая». При корректуре сохраняйте такие фразы. Не размазывайте новые шутки по всему тексту и не превращайте материал в фамильярный пост.

### Структура и Markdown

- Заголовки не нумеруются.
- `#` — название статьи.
- `##` — крупный вопрос или этап: «Зачем?», «Как установить приложение?», «Что дальше?».
- `###` — отдельный путь, платформа или сервер.
- `####` — конкретная операция.
- Внутри одного уровня сохраняйте согласованность: вопросительные заголовки не перемешивайте случайным образом с существительными и повелительными формами.
- Пошаговые клики оформляйте нумерованным списком.
- Параметры, характеристики и поля формы оформляйте маркированным списком.
- Маршруты по интерфейсу пишите через стрелки: `**Настройки → Правила трафика → Правила от сообщества**`.
- Элементы интерфейса, важные названия и кнопки выделяйте **жирным**.
- Команды, пути, порты, версии, ключи и точные значения оформляйте `моноширинным`.
- Многострочные команды и вывод помещайте в fenced code blocks с языком: `bash`, `powershell`, `sshconfig`, `text`.
- Используйте осмысленные Markdown-ссылки, а не голые URL.
- Неупомянутые настройки явно предлагайте оставить по умолчанию только там, где это действительно важно для воспроизводимости.

### Терминология

Сохраняйте написание: `VLESS`, `VPS`, `SSH`, `IP`, `IPv4`, `WSL`, `BIOS/UEFI`, `Xray`, `3x-ui`, `v2RayTun`; `ВПН ВИКТОР` — имя конфигурации. Английские названия полей 3x-ui после переключения панели на английский сохраняйте буквально. `backend`/`frontend`, `inbound`/`outbound` без необходимости не переводите.

Важное текущее расхождение: первая статья последовательно использует русское «ВПН», а вторая — латинское «VPN», включая заголовок. Это результат отдельных редакционных итераций. Не запускайте глобальную замену по всему проекту без отдельного указания.

### Чего не добавлять

- юридические дисклеймеры и нравоучения;
- общие предупреждения без практической пользы;
- маркетинговые эпитеты;
- длинные вступления;
- повторный пересказ предыдущих разделов;
- новые факты, советы и шутки «от себя»;
- лишние технические шаги «на всякий случай».

Если пользователь просит только «причесать» текст, исправляйте орфографию, пунктуацию, согласование, тавтологию и явно кривые предложения. Сохраняйте факты, порядок, шутки и авторский голос. Правка должна быть точечной и практически незаметной.

## Разница между аудиториями

`01-connect-vpn-victor.md` предназначен для людей, далёких от ИТ. Термины нужно кратко объяснять, а действия — описывать покликово. Не предполагайте знание терминала, протоколов или сетевой архитектуры.

`02-setup-two-node-vpn.md` предназначен для технически грамотного читателя, знакомого с терминалом. При этом инструкция должна оставаться воспроизводимой: команды даются готовыми, должно быть понятно, где их выполнять и какой результат ожидать.

- Пользователь предпочитает идти абзац за абзацем и вносить точечные правки.
- Если раздел или формулировка объявлены «фиксируем», не возвращайтесь к ним без нового прямого указания.
- При просьбе изменить конкретный фрагмент не переписывайте соседние разделы ради стилистической симметрии.
- Не выдавайте черновой текст вместо изменения файла, если пользователь явно просит обновить файл.

- Для нестабильных фактов о сервисах, приложениях, версиях и интерфейсах проверяйте актуальные первичные источники. Не подменяйте проверенный личный опыт пользователя найденной в интернете общей рекомендацией.

## Облачные агенты Cursor

Пользователь планирует продолжать работу над этим репозиторием через Cursor Cloud Agents, а не только локально.

- Репозиторий к Cloud Agent подключается через Cursor GitHub App: [Dashboard → Integrations](https://cursor.com/dashboard/integrations), не через поле PAT в Settings IDE.
- Для обычных правок, push и PR достаточно GitHub App.
- Для расширенных операций через `gh`/API (создание и удаление репозиториев, управление Pages и т.п.) PAT кладут в [Cloud Agents → Secrets](https://cursor.com/dashboard/cloud-agents). Лучше не называть секрет `GH_TOKEN`: Cursor может подставить туда собственный App-токен `ghs_…`. Удобнее `GITHUB_PAT` / `MY_GH_TOKEN` и явная авторизация `gh` из этого секрета.
- Запуск: режим Cloud в IDE или [cursor.com/agents](https://cursor.com/agents) с выбором `vchigrinsky/wizard`.

## Известные сетевые наблюдения, не включённые в статьи

Во время воспроизведения встречались маршрутно-зависимые проблемы, которые не свелись к настройкам клиента или сервера:

- SSH к российскому Timeweb устанавливал TCP-соединение, но серверный SSH banner не доходил до клиента из некоторых исходных сетей и VPN-выходов; с других маршрутов соединение работало.
- На одном сервере Beget в Казахстане TCP/443 до `github.com`, `api.github.com` и `raw.githubusercontent.com` не устанавливался: исходящие SYN уходили, ответа не было, тогда как другие HTTPS-сайты открывались.

Эти эпизоды не получили универсального исправления и не были добавлены в готовые статьи. Если проблема повторится, рассматривайте маршрутизацию, peering и фильтрацию конкретного направления; не объявляйте автоматически виновником DNS, TLS, серверный firewall или ТСПУ без пакетных логов.
