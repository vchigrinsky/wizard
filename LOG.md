# wizard — LOG

## Entrypoint

Репозиторий материалов Telegram-канала [vuutya](https://t.me/vuutya): лонгриды про прикладные ИТ-штуки (VPN, сети, саморазвёрнутые сервисы) и project site GitHub Pages.

Публичный сайт: [vchigrinsky.github.io/wizard](https://vchigrinsky.github.io/wizard/).  
Репозиторий: [github.com/vchigrinsky/wizard](https://github.com/vchigrinsky/wizard).  
Единственная рабочая ветка: `master`.

Форматы материалов: веб-страница (Pages), исходный Markdown, при необходимости PDF.
Структура: `docs/` — статьи с навигацией для сайта; `data/` — чистые копии и файлы для скачивания/копирования; `scripts/` — автоматизация двухузловой схемы (см. `scripts/README.md`); в корне контента — `README.md`, `LOG.md`, `PUBLICATIONS.md`, `icon.png`.

Рабочие файлы `vless.md` (ключи маршрутов) и `panels.md` (доступы к панелям 3x-ui) в git не хранятся: это живые креды, оба в `.gitignore` и в `exclude` Jekyll.

### Общие правила

- Всё на русском: общение с пользователем, Markdown-документы, сообщения коммитов.
- Работаем только в `master`: коммит и сразу push в `origin/master`. Отдельное разрешение на это не нужно. Отдельные ветки — только если пользователь явно попросил.
- Когда пользователь говорит «сохраняемся» (или близкое по смыслу): обновить этот `LOG.md` (проверить текущую дату, дописать историю в блок нужной даты сверху, актуализировать current state), затем коммит и push.
- Новые правила в шапку лога добавлять только по явной отмашке пользователя. Самостоятельно можно править только current state и исторические блоки.
- На титульник (`README.md`) статью добавляем только по явной отмашке. До этого черновик можно вести в `data/` без появления в оглавлении.
- По явной отмашке «вывести в docs»: (1) продублировать чистый текст в `docs/`; (2) в `docs/` добавить навигацию «← Все материалы» / «Скачать PDF» / «Скопировать Markdown»; (3) в `data/` пересобрать PDF через `mdpdf`. После этой манипуляции черновик дальше ведём синхронно.
- При любых правках уже синхронизированных статей всегда и безусловно: (1) зеркально обновить одноимённые файлы в `docs/` и `data/` — в `data/` без навигационных ссылок «← Все материалы» / «Скачать …» / «Скопировать …»; (2) пересобрать PDF в `data/` через `mdpdf`. Исключения (правка только в `docs/` или только в `data/`) — только если пользователь явно так сказал.
- Слог анонсов и сервисных постов канала, а также тон формулировок в статьях — по `PUBLICATIONS.md`. Новые посты канала дописывать туда (свежие сверху). При предложении текстов опираться на этот файл, а не выдумывать другой голос.
- Буква «ё»: пишем с «ё» (`ещё`, `всё`, `включён`, `зелёный`), не заменяем на «е». Так уже сделано в статьях 1–2; в новых текстах держать так же.

## История

## 2026-08-05

Написана автоматизация в `scripts/`: `vpn_ssh_key.py` (шаг 0), `vpn_build_route.py` (шаг 1), `vpn_check_routes.py` (шаг 2), `vpn_panel_creds.py` (доступы к панелям) и общий `vpnkit.py`. Панель 3x-ui `v3.5.0` управляется через собственное HTTP API: токен лежит в `/etc/x-ui/install-result.env`, спека доступна на `/panel/api/openapi.json`, запросы идут через `curl` на самом сервере по `127.0.0.1`. Скрипты идемпотентны и одинаково работают на голом сервере и на уже настроенном. Проверка маршрутов сделана на локальном `xray` с SOCKS-прокси, а не на v2RayTun: у последнего на macOS нет ни CLI, ни AppleScript-словаря.
