# wizard — LOG

## Entrypoint

Репозиторий материалов Telegram-канала [vuutya](https://t.me/vuutya): лонгриды про прикладные ИТ-штуки (VPN, сети, саморазвёрнутые сервисы) и project site GitHub Pages.

Публичный сайт: [vchigrinsky.github.io/wizard](https://vchigrinsky.github.io/wizard/).  
Репозиторий: [github.com/vchigrinsky/wizard](https://github.com/vchigrinsky/wizard).  
Единственная рабочая ветка: `master`.

Форматы материалов: веб-страница (Pages), исходный Markdown, при необходимости PDF.
Структура: `docs/` — статьи с навигацией для сайта; `data/` — чистые копии и файлы для скачивания/копирования; `scripts/` — автоматизация двухузловой схемы (см. `scripts/README.md`); в корне контента — `README.md`, `LOG.md`, `PUBLICATIONS.md`, `icon.png`.

Рабочие файлы `vless.md` (ключи маршрутов) и `panels.md` (доступы к панелям 3x-ui) в git не хранятся: это живые креды, оба в `.gitignore` и в `exclude` Jekyll.

### Общие правила

- Всё на русском: общение с пользователем, Markdown-документы, сообщения коммитов.
- Работаем только в `master`: коммит и сразу push в `origin/master`. Отдельное разрешение на это не нужно. Отдельные ветки — только если пользователь явно попросил.
- Когда пользователь говорит «сохраняемся» (или близкое по смыслу): обновить этот `LOG.md` (проверить текущую дату, дописать историю в блок нужной даты сверху, актуализировать current state), затем коммит и push.
- Новые правила в шапку лога добавлять только по явной отмашке пользователя. Самостоятельно можно править только current state и исторические блоки.
- На титульник (`README.md`) статью добавляем только по явной отмашке. До этого черновик можно вести в `data/` без появления в оглавлении.
- По явной отмашке «вывести в docs»: (1) продублировать чистый текст в `docs/`; (2) в `docs/` добавить навигацию «← Все материалы» / «Скачать PDF» / «Скопировать Markdown»; (3) в `data/` пересобрать PDF через `mdpdf`. После этой манипуляции черновик дальше ведём синхронно.
- При любых правках уже синхронизированных статей всегда и безусловно: (1) зеркально обновить одноимённые файлы в `docs/` и `data/` — в `data/` без навигационных ссылок «← Все материалы» / «Скачать …» / «Скопировать …»; (2) пересобрать PDF в `data/` через `mdpdf`. Исключения (правка только в `docs/` или только в `data/`) — только если пользователь явно так сказал.
- Слог анонсов и сервисных постов канала, а также тон формулировок в статьях — по `PUBLICATIONS.md`. Новые посты канала дописывать туда (свежие сверху). При предложении текстов опираться на этот файл, а не выдумывать другой голос.
- Буква «ё»: пишем с «ё» (`ещё`, `всё`, `включён`, `зелёный`), не заменяем на «е». Так уже сделано в статьях 1–2; в новых текстах держать так же.

## История

## 2026-08-06

**Расследование «работает через xray, не работает через v2RayTun».** Исходный симптом: маршруты с российским узлом в `timeweb` в v2RayTun работали, а в `selectel` и `vpsville` — нет, хотя по тем же ключам через локальный `xray` проходило всё.

Что установлено надёжно:

- **Сеть и ТСПУ к этому симптому отношения не имеют.** Маршруты проверены из двух независимых сетей — Ростелеком/Екатеринбург (AS12389) и Сбербанк/Москва (AS45000). В обеих TCP до всех узлов за ~30 мс без отказов, туннели поднимаются, 10 МБ прокачиваются, UDP/DNS ходит. `selectel` и `vpsville` работали не хуже `timeweb`.
- **Конфигурации узлов идентичны.** Сравнение inbound'ов, routing, sniffing рабочего и нерабочего узла — различий ноль.
- **Ключи идентичны.** Экспорт профиля из v2RayTun сверен с `vless.md` по восьми полям (uuid, адрес, порт, publicKey, shortId, sni, fingerprint, spiderX) — совпадают все, `sid` в текущем пуле сервера.

Пакетный анализ отказавшего сеанса (tcpdump на узле, фильтр по IP клиента): 2417 соединений за две минуты, 2415 с RST; жёсткий потолок — ни одно не переросло 12.7 КБ вниз и 2.3 КБ вверх; медиана 28 пакетов и ~6.4 КБ от сервера; RST всегда со стороны клиента; счётчик клиента на сервере не вырос, то есть сессии не были авторизованы. Такой след дают два разных механизма — провал аутентификации REALITY (сервер уходит в подмену на настоящий `www.yandex.ru`) и убийство соединения фильтром сразу после рукопожатия. Различить их можно только логом сервера, но к моменту включения лога неисправность уже ушла.

**Итог: ошибку не поймали, механизм не доказан.** Неисправность исчезла после полного перезапуска ядра Xray на `selectel_ru` и не воспроизводится. Гипотеза «горячее применение конфига (`applied through the core API, no restart needed`) ломает ядро» проверена намеренно на `vpsville_ru` — **не подтвердилась**. Поэтому поставлен сторож и включены подробные логи: следующий случай должен быть пойман с доказательствами.

**Отдельно найден и доказан реальный сетевой блок.** Маршрут `selectel_ru → bigvds_nl` не работал по двум причинам сразу. Первая — битый outbound: ядро отвергало его с `Failed to build REALITY config > empty "password"`, он лежал в шаблоне панели, но в рабочий конфиг не попадал; починено пересозданием. Вторая — Selectel дропает TLS на всю подсеть `109.104.153.0/24`: TCP проходит, приветствие TLS глотается, MTU 1500 в норме, в обратную сторону всё работает, фаервол на bigvds выключен. Доказано решающим тестом: один и тот же свежий outbound работает при проверке с `timeweb_ru` (46 мс, выход NL) и уходит в таймаут с `selectel_ru`. Конфигом это не лечится. Связка удалена из `vless.md`, осиротевшие клиент, outbound и routing rule сняты с обоих узлов.

**Что известно про ТСПУ из исследований** (сопоставлено с опытами): инспекция на L3/L4 (адреса, порты, флаги, размеры и частоты пакетов) и на L7 — извлечение SNI, отпечатки JA3/JA4, поведенческий анализ первых пакетов и ретрансмиссий. Действия: drop, инъекция TCP RST, ограничение скорости. Порт 443 инспектируется глубоко, высокие порты — поверхностно. Есть данные о модификации первых байт TLS ClientHello вместо простого дропа. Источники: [TGV](https://tgvpn.io/en/tspu-dpi-russia-2030-analysis.html), [Zona](https://en.zona.media/article/2026/04/07/russian_internet_censorship_2026), [ACF](https://fbk.info/files/acf-internet-report-EN.pdf).

Добавлены `scripts/vpn_proxy.py` (локальный SOCKS5/HTTP-прокси поверх маршрута, с фоновым режимом через launchd), `scripts/vpn_watch.py` (сторож маршрутов) и `scripts/direct` (обёртка для запуска в обход прокси). В `vpnkit.py` добавлен `env_without_proxy()` — подпроцессы `curl` больше не наследуют прокси из окружения, иначе проверка маршрутов мерила бы через прокси вместо туннеля.
